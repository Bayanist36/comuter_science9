### 3\. Изучение нового материала (20 мин)

**Учитель:** Данные не обязательно хранить целиком: достаточно нескольких переменных, которые обновляются по одному числу за шаг. Всё искусство такой обработки — правильно выбрать начальные значения, не потерять последний элемент и вовремя остановиться.

#### 3\.1. Поток и массив: две модели работы с данными (~4 мин)

<note type="quote">
  Поток данных — последовательность значений, которые поступают по одному, обрабатываются сразу и не сохраняются целиком.
</note>

**Учитель:** Когда все числа уже лежат в массиве, можно пройти по ним сколько угодно раз: сначала найти сумму, потом минимум, потом посчитать чётные. У потока такого преимущества нет. Значения поступают по одному, и после перехода к следующему предыдущее теряется, если его специально не сохранить. Поэтому все нужные характеристики приходится вычислять за один проход, обновляя набор переменных на каждом шаге.

**Учитель:** Такая модель встречается постоянно: датчик отдаёт измерения, сервер принимает запросы, программа читает строки файла построчно, пользователь вводит числа с клавиатуры. Везде объём данных либо велик, либо неизвестен, поэтому массив оказывается неподходящим инструментом. Обработка потока требует памяти, не зависящей от длины последовательности: три-четыре переменные обслуживают и десять чисел, и миллион.

**Учитель:** Отсюда главное следствие: алгоритм обработки потока состоит из трёх частей — подготовки переменных, цикла чтения с обновлением и вывода результата. Ошибка в любой из трёх частей делает программу неверной, даже если сам цикл написан правильно.

| Свойство | Массив | Поток |
|:---|:---|:---|
| Доступ к элементам | к любому по индексу | только к текущему |
| Длина | известна заранее | часто неизвестна |
| Память | пропорциональна числу элементов | несколько переменных |
| Число проходов | сколько нужно | ровно один |
| Пример | оценки за четверть | показания датчика |

<note type="quote">
  В потоке нельзя «вернуться назад»: если значение понадобится позже, его нужно сохранить сразу. Именно поэтому набор переменных продумывают до написания цикла, а не добавляют по ходу.
</note>

#### 3\.2. Счётчик и сумма (~4 мин)

**Учитель:** Две самые простые величины — количество и сумма. Счётчик увеличивают на единицу при каждом обработанном элементе, сумму — на значение элемента. Обе переменные инициализируются нулём до цикла, потому что ноль не искажает ни количество, ни сумму: прибавление к нулю не меняет результата.

**Учитель:** Среднее арифметическое вычисляют один раз, после завершения цикла: разделить сумму на количество. Считать его внутри цикла бессмысленно — на каждом шаге получалось бы новое промежуточное значение, а нужно итоговое. Деление на количество требует проверки: если последовательность оказалась пустой, количество равно нулю, и операция выдаст ошибку выполнения.

**Учитель:** Счётчик удобен тем, что из него получаются и другие величины: доля элементов, удовлетворяющих условию, равна отношению такого счётчика к общему количеству. Для этого заводят второй счётчик — например, отдельно считают чётные числа. Оба счётчика обновляются в одном и том же цикле.

<note type="quote">
  Среднее внутри цикла и деление на ноль — две самые частые ошибки этой темы. Сначала цикл, потом среднее; перед делением — проверка count > 0.
</note>

```python
total = 0
count = 0
while True:
    x = int(input("Число (0 — конец): "))
    if x == 0:
        break
    total += x
    count += 1
print("Сумма:", total, "Количество:", count)
if count > 0:
    print("Среднее:", total / count)
```

#### 3\.3. Минимум и максимум на лету (~4 мин)

**Учитель:** Поиск минимума в массиве мы делали, начиная с первого элемента. В потоке первого элемента ещё нет в памяти, поэтому используют один из двух приёмов. Первый: прочитать первое значение до цикла и объявить его текущим рекордом, а цикл начать со второго элемента. Второй: завести признак «рекорда пока нет» и заполнять его при первом же значении.

**Учитель:** Начальное значение 0 кажется удобным, но верно только для задач, где числа заведомо неотрицательны. Если все значения последовательности отрицательны, максимум останется равным нулю, то есть числу, которого в данных не было. Это самая известная ловушка темы, и её проверяют на примере из одних отрицательных чисел.

**Учитель:** Вместе с рекордом хранят его номер: при обновлении значения обновляют и номер. Если нужны оба рекорда, заводят четыре переменные — минимум с номером и максимум с номером. Все они обновляются в одном проходе, и это не удваивает работу: сравнений становится вдвое больше, а проход остаётся один.

<note type="quote">
  Строгое сравнение mx > текущего рекорда фиксирует первое вхождение максимума, нестрогое — последнее. В формулировке «номер первого максимума» нужно строгое сравнение, в «номер последнего» — нестрогое.
</note>

```python
mx = int(input())       # первое значение - рекорд
nmx = 1
i = 1
while True:
    x = int(input())
    if x == 0:
        break
    i += 1
    if x > mx:
        mx = x
        nmx = i
print(mx, nmx)      # для 12 5 19 7 19 3 0 выведет "19 3"
```

#### 3\.4. Когда останавливаться: признак конца (~4 мин)

**Учитель:** У последовательности должен быть конец, иначе цикл не завершится. Способов задать конец три. Первый — заранее известно количество: читаем ровно n значений, цикл for с range(n). Второй — сторожевой признак: последовательность заканчивается специальным значением, которого не может быть среди данных, например −1 для температуры или 0 для натуральных чисел. Третий — конец файла: цикл читает строки, пока они есть.

**Учитель:** Проверку признака ставят до обработки значения: сторож не является элементом данных и не должен попасть ни в сумму, ни в счётчик, ни в сравнение с рекордом. Если поставить проверку после накопления, в результат попадёт лишнее значение, и ответ будет неверным при формально правильном коде.

**Учитель:** Отдельный случай — пустая последовательность: сторож приходит первым. Программа должна это пережить: сумма останется нулевой, количество нулевым, а среднее и минимум выводить нельзя. Проверка крайних случаев — часть решения, а не добавка к нему.

| Способ | Как записывают | Когда применяют |
|:---|:---|:---|
| Количество известно | for i in range(n) | данные фиксированной длины |
| Сторожевое значение | while x != 0 | ввод с клавиатуры, простые задачи |
| Конец файла | for line in f | обработка текстовых файлов |
| Флаг пользователя | while True с break | сложное условие выхода |

<note type="quote">
  Сторожевое значение выбирают так, чтобы оно не встречалось в данных. Если последовательность может содержать нули, ноль плохой сторож: настоящий нуль оборвёт обработку раньше времени. Тогда берут −1 или задают количество.
</note>

#### 3\.5. Что ещё считается за один проход (~4 мин)

**Учитель:** Из четырёх базовых величин получаются производные. Среднее — сумма, делённая на количество. Размах — разность максимума и минимума. Доля элементов, удовлетворяющих условию, — отношение подходящего счётчика к общему количеству. Все они не требуют новых проходов: достаточно того, что уже накоплено.

**Учитель:** Более сложные величины тоже укладываются в один проход, если добавить переменную. Второй максимум ищут, храня два рекорда: новый элемент сравнивают с первым, а прежний первый становится вторым. Такой приём показывает главное правило темы: число переменных растёт, число проходов — нет.

| Величина | Что нужно хранить | Когда вычисляют |
|:---|:---|:---|
| Количество | счётчик | в цикле |
| Сумма | накопитель | в цикле |
| Среднее | сумму и количество | после цикла |
| Минимум и максимум | два рекорда | в цикле |
| Размах | минимум и максимум | после цикла |
| Количество чётных | отдельный счётчик | в цикле |

<note type="quote">
  Не путайте «количество подходящих элементов» с «суммой подходящих». Для среднего чётных нужны два счётчика: сумма чётных и их количество; делить сумму чётных на общее количество нельзя.
</note>

### 4\. Первичное закрепление (12 мин)

**Учитель:** Теперь закрепим материал. Работаем по заданиям — часть устно, часть письменно.

**Задание 1. Трассировка накопителей.** Последовательность 6, −3, 14, 0 (0 — конец) обрабатывается программой, которая считает сумму, количество, минимум и максимум. Заполните таблицу значений после каждого шага и найдите итоговые величины.

**Задание 2. Среднее без массива.** Напишите фрагмент программы, которая читает числа до нуля и выводит их среднее арифметическое. Что выведет программа, если первым придёт ноль? Как нужно изменить программу, чтобы в этом случае выводилось сообщение «данных нет»?

**Задание 3. Минимум и максимум на лету.** Последовательность состоит только из отрицательных чисел: −5, −2, −9, −1 (последнее — конец). Ученик нашёл минимум, начав со значения 0, и получил верный ответ. Затем он тем же способом стал искать максимум и получил 0. Какой ответ верный и почему во втором случае приём не сработал?

**Задание 4. Выбор условия остановки.** Вам нужно обработать результаты измерений температуры за сутки: значения могут быть любыми, в том числе нулевыми и отрицательными, количество измерений известно и равно 1440. Предложите условие остановки и объясните, почему сторожевой ноль здесь не подходит.

**Задание 5. Найдите ошибку.** Программа должна вывести среднее арифметическое последовательности, заканчивающейся нулём:
total = 0; count = 0; while True: x = int(input()); total += x; if x == 0: break; count += 1; print(total / count).
Найдите ошибки и запишите исправленный вариант.

**Задание 6. Практическая работа на компьютере.** В среде Python создайте файл stream.py. Программа должна читать целые числа до нуля и выводить четыре строки: количество, сумму, среднее с двумя знаками после запятой (округление через round) и максимум. Проверьте работу на наборе 5, 12, 3, 8, 0, затем на наборе с отрицательными числами −4, −10, −2, 0 и на пустом наборе — сразу 0.

**Учитель:** Проверим. Поднимите руку, у кого получился другой ответ. Разберём вместе.

*Ожидаемый ответ:* Шаг 1: x = 6, total = 6, count = 1, min = 6, max = 6. Шаг 2: x = −3, total = 3, count = 2, min = −3, max = 6. Шаг 3: x = 14, total = 17, count = 3, min = −3, max = 14. Шаг 4: x = 0 — сторож, остановка. Итог: сумма 17, количество 3, минимум −3, максимум 14, среднее 17/3 ≈ 5,67.

*Ожидаемый ответ:* Нужны две переменные: total и count; после цикла — проверка if count > 0: print(total / count) else: print("данных нет"). Если первым придёт ноль, цикл сразу прервётся, count = 0, и без проверки произойдёт деление на ноль — программа завершится с ошибкой. С проверкой будет выведено «данных нет».

*Ожидаемый ответ:* Верный максимум равен −1. Начальное значение 0 больше любого элемента данных, поэтому условие «элемент больше текущего максимума» ни разу не выполнится при строгом сравнении, и в ответе останется число, которого в данных не было. Для минимума ноль случайно оказался безвредным: любое отрицательное число меньше нуля, и рекорд обновляется. Надёжное решение одно — брать начальное значение у первого элемента последовательности.

## Приложение: опорный конспект для доски

```
ОБРАБОТКА ПОТОКА ДАННЫХ

МАССИВ: все n значений в памяти, проходов сколько угодно
ПОТОК:  только текущее значение, ОДИН проход, память O(1)

КАРКАС ПРОГРАММЫ
  total = 0   count = 0        <- до цикла
  while True:
      x = ввод
      if x == СТОП: break      <- проверка ДО обработки
      total += x
      count += 1               <- обновление в цикле
  среднее = total / count      <- после цикла (count > 0!)

РЕКОРДЫ
  mx = ПЕРВЫЙ элемент (не 0!)
  if x > mx: mx = x; nmx = i
  строгое >  -> первое вхождение
  нестрогое >= -> последнее

УСЛОВИЕ ОСТАНОВКИ: количество | сторож | конец файла

ПРОИЗВОДНЫЕ: среднее = сумма/кол-во, размах = max-min
КРАЙНИЕ СЛУЧАИ: пустая последовательность, один элемент
```
