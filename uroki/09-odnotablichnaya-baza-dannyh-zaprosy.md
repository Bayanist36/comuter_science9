**Образовательная:** сформировать понятия «база данных», «запись», «поле», «тип поля», «первичный ключ»; научить проектировать структуру однотабличной базы данных и составлять запросы с условиями И и ИЛИ и сортировкой в LibreOffice Base.

### 2\. Актуализация знаний (4 мин)

### 3\. Инструктаж по практической работе (5 мин)

**Учитель:** База данных начинается не с ввода строк, а с проекта: пока не выбраны поля, типы и ключ, любая таблица остаётся списком. Запрос превращает бытовой вопрос «какие книги мне подходят?» в формальное условие, которое компьютер проверяет для каждой записи.

#### 3\.1. Таблица, запись и поле (~1 мин)

<note type="quote">
  База данных — организованная совокупность данных, которая хранится по определённым правилам и позволяет находить, изменять и обрабатывать нужные сведения.
</note>

<note type="quote">
  Запись — строка таблицы базы данных со сведениями об одном объекте. Поле — столбец таблицы, описывающий одно свойство всех объектов.
</note>

**Учитель:** Любая база данных отвечает на три вопроса: что храним, как храним и как ищем. Ответ на первый задаёт **объект**: книга, ученик, деталь, заказ. Ответ на второй — структуру таблицы. Ответ на третий — запросы, которые мы сегодня научимся составлять.

**Учитель:** В табличной базе данных сведения об объекте занимает одна строка. Её называют **записью**. Все строки устроены одинаково: первый столбец хранит одно свойство, второй — другое. Столбец называют **полем**, и именно поле, а не отдельная ячейка, является единицей структуры.

**Учитель:** Однотабличная база данных описывает объекты одного вида и не содержит связей между таблицами. Этого достаточно для библиотеки личных книг, каталога деталей или списка фильмов: все свойства относятся к одному объекту и повторяются от записи к записи.

| Часть таблицы | Что описывает | Пример в таблице «Книги» |
|:---|:---|:---|
| Запись | один объект целиком | книга «Хоббит» |
| Поле | одно свойство всех объектов | Год издания |
| Значение | характеристика одного объекта | 1937 |
| Ключ | поле, уникальное для каждой записи | Код книги |

<note type="quote">
  Таблица в тетради и таблица в базе данных выглядят одинаково, но в базе данных каждая ячейка имеет тип, а две полностью совпадающие записи недопустимы.
</note>

#### 3\.2. Проектирование таблицы и типы полей (~1 мин)

<note type="quote">
  Тип поля — правило, которое задаёт вид допустимых значений поля и операции, разрешённые над ними.
</note>

**Учитель:** Проектирование идёт в пять шагов. Сначала называют объект, затем выписывают все его свойства, которые нужно хранить, затем убирают составные значения, затем подбирают тип каждому полю и только в конце назначают ключ. Пропущенный шаг мстит позже: переделывать структуру с уже введёнными данными намного дороже, чем продумать её на бумаге.

**Учитель:** Главное правило проектирования — **атомарность значения**: в одной ячейке хранится один факт. Запись «Толкин, Хоббит» в одном поле кажется удобной, но по ней нельзя отдельно отсортировать книги по автору и нельзя найти все книги Толкина запросом по равенству.

**Учитель:** Тип поля — не формальность. Числовое поле можно сложить и сравнить по величине, текстовое — только сравнить посимвольно. Логическое поле удобно для отметок «да/нет», а счётчик сам выдаёт новое число при добавлении записи, поэтому его почти всегда используют для ключа.

| Тип поля | Что хранит | Пример |
|:---|:---|:---|
| Текстовый | до 255 символов | Автор: Толкин |
| Целое | целые числа | Страниц: 320 |
| Денежный | числа с копейками | Цена: 750,50 |
| Дата | дату и время | 21.09.1937 |
| Логический | да или нет | Прочитана: да |
| Счётчик | автоматическую нумерацию | Код: 1, 2, 3 |

<note type="quote">
  Если цену хранить в текстовом поле, книга за 1290 рублей при сортировке встанет раньше книги за 390: сравниваются символы, а символ «1» меньше символа «3».
</note>

```text
Таблица «Книги» (структура)
Код      Счётчик            ключ
Автор    Текстовый, 40
Название Текстовый, 80
Год      Целое
Жанр     Текстовый, 20
Страниц  Целое
Цена     Денежный
Прочитана Логический
```

#### 3\.3. Первичный ключ (~1 мин)

<note type="quote">
  Первичный ключ — поле или набор полей, значения которых однозначно определяют каждую запись таблицы.
</note>

**Учитель:** Без ключа запись нельзя надёжно назвать: если в таблице две книги Толкина, команда «удалить книгу Толкина» неоднозначна. Ключ снимает эту неоднозначность: он указывает ровно на одну строку.

**Учитель:** Ключ бывает естественным и искусственным. Естественный берут из самих данных: номер паспорта, инвентарный номер, ISBN. Искусственный добавляют специально — обычно это поле-счётчик с именем Код. Искусственный ключ удобнее: он короткий, никогда не меняется и не зависит от того, правильно ли введены содержательные данные.

| Кандидат в ключ | Годится | Причина |
|:---|:---|:---|
| Код книги | да | значения не повторяются |
| Фамилия автора | нет | у Толкина в таблице две книги |
| Название книги | нет | названия могут совпасть |
| Год издания | нет | много книг одного года |
| Телефон читателя | нет | может измениться или отсутствовать |

<note type="quote">
  В таблице «Расписание» ни день недели, ни номер урока по отдельности не уникальны, а вместе они образуют составной ключ: день + номер урока + класс.
</note>

#### 3\.4. Запрос: условие отбора (~1 мин)

<note type="quote">
  Запрос — обращение к базе данных, которое по заданному условию отбирает, сортирует или вычисляет нужные записи.
</note>

**Учитель:** Запрос устроен как сито: база берёт записи по одной и проверяет условие. Если условие истинно, запись попадает в результат, если ложно — отбрасывается. Никакого «понимания смысла» не происходит, поэтому формулировка должна быть точной.

**Учитель:** Условие собирают из простых сравнений и логических связок. Сравнение всегда применяется к одному полю и одному значению. Связка И требует, чтобы выполнялись оба сравнения, связка ИЛИ — хотя бы одно. Отсюда практическое правило: И делает выборку уже, ИЛИ — шире.

| Оператор | Смысл | Пример |
|:---|:---|:---|
| = | равно | Жанр = "сказка" |
| <> | не равно | Год <> 1954 |
| > и < | больше и меньше | Цена > 500 |
| И | верны оба условия | Жанр = "сказка" И Цена < 500 |
| ИЛИ | верно хотя бы одно | Год < 1900 ИЛИ Год > 2000 |

<note type="quote">
  Запрос «Жанр = "сказка" ИЛИ Жанр = "фэнтези" И Цена < 500» работает не так, как читается: сначала выполняется И, потом ИЛИ. Для дешёвых книг двух жанров нужны скобки.
</note>

```text
Словами: «приключения толще 500 страниц»
Жанр = "приключения" И Страниц > 500

Словами: «сказки или фэнтези дешевле 500»
(Жанр = "сказка" ИЛИ Жанр = "фэнтези") И Цена < 500
```

#### 3\.5. Сортировка и запись запроса на SQL (~1 мин)

**Учитель:** Сортировка не отбирает записи, а расставляет их. Поэтому число строк в результате от неё не меняется: если записей стало меньше, значит, изменилось условие отбора, а не порядок. Сортировать можно по нескольким полям: сначала по первому, а внутри одинаковых значений — по второму.

**Учитель:** В LibreOffice Base запрос собирают в режиме дизайна: перетаскивают поля в бланк, в строке «Условие отбора» пишут сравнения, в строке «Сортировка» выбирают направление. Для тех же действий есть текстовый язык SQL, и запись на нём читается почти как английская фраза.

<note type="quote">
  В режиме дизайна условия, которые должны выполняться одновременно, стоят в одной строке «Условие отбора». Если записать их в разные строки, Base свяжет их через ИЛИ и выборка станет шире.
</note>

```text
SELECT Название, Цена
FROM Книги
WHERE Жанр = "приключения" AND Цена > 500
ORDER BY Цена DESC
```

## Приложение: опорный конспект для доски

```
ОДНОТАБЛИЧНАЯ БАЗА ДАННЫХ

ТАБЛИЦА = ЗАПИСИ (строки) + ПОЛЯ (столбцы)
  запись  -> один объект
  поле    -> одно свойство всех объектов
  ячейка  -> одно значение, один факт

ТИПЫ ПОЛЕЙ: текст | целое | денежный | дата
            логический | счётчик

КЛЮЧ (первичный):
```
