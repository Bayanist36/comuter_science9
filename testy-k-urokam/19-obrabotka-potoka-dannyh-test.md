# 🔑 КЛЮЧИ И КРИТЕРИИ ОЦЕНИВАНИЯ (для учителя)

### Ответы к Части А (макс. 5 баллов)

1. **б** — Массив требует памяти, пропорциональной числу элементов, а поток обрабатывают несколькими переменными при любом объёме данных.
2. **в** — Только значение из самих данных гарантирует, что рекорд принадлежит последовательности и сравнение сработает при любом наборе.
3. **а** — Сторож не является элементом данных, поэтому при его появлении обработку нужно прекратить до любых накоплений.
4. **б** — Ноль добавит к сумме ничего, но будет посчитан как элемент, поэтому количество станет 4, а среднее — 4,5 вместо 6.
5. **б** — Среднее требует суммы и количества, максимум — отдельного рекорда; массив не нужен.

### Ответы к Части Б (макс. 4 балла)

**6\.** Элементов 4 (8, 3, 12, 5), сумма 8 + 3 + 12 + 5 = 28. Ноль в сумму не входит, потому что является сторожевым значением.
*Оценивание: 2 балла — ответ полный и верный; 1 балл — ответ неполный; 0 баллов — ответ неверный.*

**7\.** Минимум −5, он стоит четвёртым. Рекорд начинается с первого элемента 7, затем обновляется на −2 и на −5; сравнение строгое, поэтому номер первого вхождения.
*Оценивание: 2 балла — ответ полный и верный; 1 балл — ответ неполный; 0 баллов — ответ неверный.*

### Ответы к Части В (макс. 9 баллов)

**8\.**
*Ожидаемое решение:*

Переменные: cnt_even = 0, sum_pos = 0, cnt_pos = 0. В цикле: прочитать x, если x == 0 — break; если x % 2 == 0 — cnt_even += 1; если x > 0 — sum_pos += x, cnt_pos += 1. После цикла вывести cnt_even, а при cnt_pos > 0 — sum_pos / cnt_pos. На последовательности 4, −3, 8: чётные 4 и 8, значит cnt_even = 2; положительные 4 и 8, sum_pos = 12, cnt_pos = 2, среднее 6.0. Ответ: чётных 2, среднее положительных 6.0.

*Оценивание: 3 балла — решение полное, с обоснованием; 2 балла — верный ход с одной неточностью; 1 балл — начато верно; 0 баллов — решение отсутствует.*

**9\.**
*Ожидаемое решение:*

Одна переменная хранит только лучший результат, а второй по величине нужно помнить отдельно. Нужны два рекорда: если x больше первого, второй становится прежним первым, а первый — x; иначе если x больше второго и не равен первому, обновляется второй. Наивное решение «запомнить максимум, потом найти максимум среди остальных» требует второго прохода, которого в потоке нет. Пример: 4, 9, 9, 2 — второй по величине равен 9 (повтор), а не 4, если считать повторяющиеся значения допустимыми.

*Оценивание: 3 балла — решение полное, с обоснованием; 2 балла — верный ход с одной неточностью; 1 балл — начато верно; 0 баллов — решение отсутствует.*

**10\.**
*Ожидаемое решение:*

Программа выведет сумму 48 и максимум 22. Сумма 15 + 3 + 22 + 8 = 48 верна: ноль её не изменил, а количество в этой задаче не выводится. Максимум 22 тоже верен, но случайно: при всех положительных числах инициализация нулём не мешает. Ошибки проявятся на другом наборе: на −4, −10, −2, 0 максимум станет 0 вместо −2, а если бы выводилось количество, оно оказалось бы на единицу больше.

*Оценивание: 3 балла — решение полное, с обоснованием; 2 балла — верный ход с одной неточностью; 1 балл — начато верно; 0 баллов — решение отсутствует.*
