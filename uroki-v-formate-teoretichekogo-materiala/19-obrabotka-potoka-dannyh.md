## 1\. Главное о теме

Данные не обязательно хранить целиком: достаточно нескольких переменных, которые обновляются по одному числу за шаг. Всё искусство такой обработки — правильно выбрать начальные значения, не потерять последний элемент и вовремя остановиться.

Дальше разберём по шагам: поток и массив: две модели работы с данными; счётчик и сумма; минимум и максимум на лету; когда останавливаться: признак конца; что ещё считается за один проход.

---

## 2\. Поток и массив: две модели работы с данными

> **Определение.** Поток данных — последовательность значений, которые поступают по одному, обрабатываются сразу и не сохраняются целиком.

Когда все числа уже лежат в массиве, можно пройти по ним сколько угодно раз: сначала найти сумму, потом минимум, потом посчитать чётные. У потока такого преимущества нет. Значения поступают по одному, и после перехода к следующему предыдущее теряется, если его специально не сохранить. Поэтому все нужные характеристики приходится вычислять за один проход, обновляя набор переменных на каждом шаге.

Такая модель встречается постоянно: датчик отдаёт измерения, сервер принимает запросы, программа читает строки файла построчно, пользователь вводит числа с клавиатуры. Везде объём данных либо велик, либо неизвестен, поэтому массив оказывается неподходящим инструментом. Обработка потока требует памяти, не зависящей от длины последовательности: три-четыре переменные обслуживают и десять чисел, и миллион.

Отсюда главное следствие: алгоритм обработки потока состоит из трёх частей — подготовки переменных, цикла чтения с обновлением и вывода результата. Ошибка в любой из трёх частей делает программу неверной, даже если сам цикл написан правильно.

| Свойство | Массив | Поток |
|:---|:---|:---|
| Доступ к элементам | к любому по индексу | только к текущему |
| Длина | известна заранее | часто неизвестна |
| Память | пропорциональна числу элементов | несколько переменных |
| Число проходов | сколько нужно | ровно один |
| Пример | оценки за четверть | показания датчика |

> В потоке нельзя «вернуться назад»: если значение понадобится позже, его нужно сохранить сразу. Именно поэтому набор переменных продумывают до написания цикла, а не добавляют по ходу.

## 3\. Счётчик и сумма

Две самые простые величины — количество и сумма. Счётчик увеличивают на единицу при каждом обработанном элементе, сумму — на значение элемента. Обе переменные инициализируются нулём до цикла, потому что ноль не искажает ни количество, ни сумму: прибавление к нулю не меняет результата.

Среднее арифметическое вычисляют один раз, после завершения цикла: разделить сумму на количество. Считать его внутри цикла бессмысленно — на каждом шаге получалось бы новое промежуточное значение, а нужно итоговое. Деление на количество требует проверки: если последовательность оказалась пустой, количество равно нулю, и операция выдаст ошибку выполнения.

Счётчик удобен тем, что из него получаются и другие величины: доля элементов, удовлетворяющих условию, равна отношению такого счётчика к общему количеству. Для этого заводят второй счётчик — например, отдельно считают чётные числа. Оба счётчика обновляются в одном и том же цикле.

> Среднее внутри цикла и деление на ноль — две самые частые ошибки этой темы. Сначала цикл, потом среднее; перед делением — проверка count > 0.

```python
total = 0
count = 0
while True:
    x = int(input("Число (0 — конец): "))
    if x == 0:
        break
    total += x
    count += 1
print("Сумма:", total, "Количество:", count)
if count > 0:
    print("Среднее:", total / count)
```

## 4\. Минимум и максимум на лету

Поиск минимума в массиве мы делали, начиная с первого элемента. В потоке первого элемента ещё нет в памяти, поэтому используют один из двух приёмов. Первый: прочитать первое значение до цикла и объявить его текущим рекордом, а цикл начать со второго элемента. Второй: завести признак «рекорда пока нет» и заполнять его при первом же значении.

Начальное значение 0 кажется удобным, но верно только для задач, где числа заведомо неотрицательны. Если все значения последовательности отрицательны, максимум останется равным нулю, то есть числу, которого в данных не было. Это самая известная ловушка темы, и её проверяют на примере из одних отрицательных чисел.

Вместе с рекордом хранят его номер: при обновлении значения обновляют и номер. Если нужны оба рекорда, заводят четыре переменные — минимум с номером и максимум с номером. Все они обновляются в одном проходе, и это не удваивает работу: сравнений становится вдвое больше, а проход остаётся один.

> Строгое сравнение mx > текущего рекорда фиксирует первое вхождение максимума, нестрогое — последнее. В формулировке «номер первого максимума» нужно строгое сравнение, в «номер последнего» — нестрогое.

```python
mx = int(input())       # первое значение - рекорд
nmx = 1
i = 1
while True:
    x = int(input())
    if x == 0:
        break
    i += 1
    if x > mx:
        mx = x
        nmx = i
print(mx, nmx)      # для 12 5 19 7 19 3 0 выведет "19 3"
```

## 5\. Когда останавливаться: признак конца

У последовательности должен быть конец, иначе цикл не завершится. Способов задать конец три. Первый — заранее известно количество: читаем ровно n значений, цикл for с range(n). Второй — сторожевой признак: последовательность заканчивается специальным значением, которого не может быть среди данных, например −1 для температуры или 0 для натуральных чисел. Третий — конец файла: цикл читает строки, пока они есть.

Проверку признака ставят до обработки значения: сторож не является элементом данных и не должен попасть ни в сумму, ни в счётчик, ни в сравнение с рекордом. Если поставить проверку после накопления, в результат попадёт лишнее значение, и ответ будет неверным при формально правильном коде.

Отдельный случай — пустая последовательность: сторож приходит первым. Программа должна это пережить: сумма останется нулевой, количество нулевым, а среднее и минимум выводить нельзя. Проверка крайних случаев — часть решения, а не добавка к нему.

| Способ | Как записывают | Когда применяют |
|:---|:---|:---|
| Количество известно | for i in range(n) | данные фиксированной длины |
| Сторожевое значение | while x != 0 | ввод с клавиатуры, простые задачи |
| Конец файла | for line in f | обработка текстовых файлов |
| Флаг пользователя | while True с break | сложное условие выхода |

> Сторожевое значение выбирают так, чтобы оно не встречалось в данных. Если последовательность может содержать нули, ноль плохой сторож: настоящий нуль оборвёт обработку раньше времени. Тогда берут −1 или задают количество.

## 6\. Что ещё считается за один проход

Из четырёх базовых величин получаются производные. Среднее — сумма, делённая на количество. Размах — разность максимума и минимума. Доля элементов, удовлетворяющих условию, — отношение подходящего счётчика к общему количеству. Все они не требуют новых проходов: достаточно того, что уже накоплено.

Более сложные величины тоже укладываются в один проход, если добавить переменную. Второй максимум ищут, храня два рекорда: новый элемент сравнивают с первым, а прежний первый становится вторым. Такой приём показывает главное правило темы: число переменных растёт, число проходов — нет.

| Величина | Что нужно хранить | Когда вычисляют |
|:---|:---|:---|
| Количество | счётчик | в цикле |
| Сумма | накопитель | в цикле |
| Среднее | сумму и количество | после цикла |
| Минимум и максимум | два рекорда | в цикле |
| Размах | минимум и максимум | после цикла |
| Количество чётных | отдельный счётчик | в цикле |

> Не путайте «количество подходящих элементов» с «суммой подходящих». Для среднего чётных нужны два счётчика: сумма чётных и их количество; делить сумму чётных на общее количество нельзя.

## 7\. Разобранные примеры

### Пример 1. Сумма и среднее до нуля

**Условие.** Последовательность 4, 7, 2, 9, 0 обрабатывается программой со сторожевым значением 0. Найдите сумму, количество элементов и среднее арифметическое.

**Решение.** Начальные значения: total = 0, count = 0. Шаг 1: x = 4, не сторож, total = 4, count = 1. Шаг 2: x = 7, total = 11, count = 2. Шаг 3: x = 2, total = 13, count = 3. Шаг 4: x = 9, total = 22, count = 4. Шаг 5: x = 0 — сторож, цикл прерывается до накопления, поэтому ноль в сумму не попал.

Среднее: 22 / 4 = 5,5. Проверка: 4 + 7 + 2 + 9 = 22, элементов четыре, среднее лежит между наименьшим (2) и наибольшим (9) — значит, порядок величины верен.

**Ответ:** сумма 22, количество 4, среднее 5,5. Если бы проверка сторожевого значения стояла после total += x, сумма стала бы 22, но количество 5, а среднее 4,4 — типичная ошибка.

### Пример 2. Максимум и его номер

**Условие.** Дан поток 12, 5, 19, 7, 19, 3. Найдите максимальное значение и номер его первого вхождения.

**Решение.** Рекорд берём у первого элемента: mx = 12, nmx = 1. Второй элемент 5 не больше 12 — рекорд не меняется. Третий 19 больше 12 — mx = 19, nmx = 3. Четвёртый 7 и пятый 19 не больше текущего рекорда, потому что сравнение строгое. Шестой 3 тоже не больше.

Номер третьего элемента равен 3 при нумерации с единицы и 2 при нумерации с нуля. В формулировке «номер» обычно имеют в виду нумерацию с единицы, но в программе удобнее хранить индекс, поэтому к нему прибавляют единицу при выводе.

**Ответ:** максимум 19, номер первого вхождения 3. Для номера последнего вхождения (5) понадобилось бы нестрогое сравнение: 19 не больше 19, но равно, и рекорд обновился бы.

### Пример 3. Две величины в одном проходе

**Условие.** Последовательность 15, 8, 22, 3, 10, 0 (0 — конец). Найдите количество чётных чисел и наибольшее из чисел, кратных 5.

**Решение.** Заводим три переменные: cnt — количество чётных, mx5 — максимум кратных пяти, есть — признак того, что такое число уже встретилось. Шаг 1: 15 нечётное, кратно 5 → mx5 = 15, есть = True. Шаг 2: 8 чётное → cnt = 1, на 5 не делится. Шаг 3: 22 чётное → cnt = 2. Шаг 4: 3 не подходит ни туда, ни туда. Шаг 5: 10 чётное → cnt = 3, кратно 5, но 10 не больше 15. Шаг 6: 0 — сторож, остановка.

**Ответ:** чётных чисел 3 (8, 22, 10), максимум среди кратных 5 равен 15. Признак «есть» нужен на случай, когда кратных пяти в последовательности не окажется вовсе: тогда выводить максимум нельзя, и программа должна сообщить, что таких чисел нет.
